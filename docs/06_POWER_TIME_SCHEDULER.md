# 06. 한국 시간·업데이트 스케줄·전력 정책

## 2026-11-05 감독·실행 경계

- 동일 RunCycle을 ICyclePlatform으로 Host/E1001에서 실행한다. 저전압/시각 불신/
  네트워크 예산/실패 렌더 재시도를 Host에서 검증하며 기기 효과는 별도 어댑터에 둔다.
- 현재 loopTask를 90초 task watchdog에 등록하고 주기 단계 및 포털 진행에서 Feed한다.
  SDK 기본 idle timeout을 함께 90초로 변경하는 영향은 ADR 0010에 명시했다.
  10분 포털을 지원하되 별도 타이머 task가 멈춘 앱을 대신 Feed하지 않는다.
- 60초 네트워크 예산은 전체 active-time 보장이 아니다. 요청/본문/패널 제한 및
  watchdog은 별도 계층이며 실제 DNS/header/TLS/전류 상한은 실기 검증이 필요하다.
- 화면 실패는 다음 주기에 재시도하고, 절전 전 RTC에도 성공한 CRC로 기록하지 않는다.
- KRX 전체 휴장/NXT·통합 거래시간과 실 API·전류 검증은 계속 BLOCKED다.

## 시간 모델
- Unix UTC epoch 내부 저장, KST(UTC+9) 출력; NTP/RTC 동기화 성공·실패 상태 분리.
- HTTPS 검증을 위해 인증서 시간 검증 가능한 시계를 확보해야 하며, RTC 유효성 검사 실패 시 HTTPS 우회 금지.
- 일정은 자료 **발표시각 + 제공지연** 기준으로 계산; 단순 매 N분 polling으로 트래픽을 낭비하지 않는다.
- 주말·연휴/거래정지일은 **거래소별 달력** 검토. 공휴일 파일 없이 월~금만 영업일이라고 결론내리지 않는다.

## Sleep 스테이트머신
- `ACTIVE_FETCH → RENDER_IF_CHANGED → (USB ? IDLE : SET_WAKE_ALARM → DEEP_SLEEP)`.
- Deep Sleep에서 버튼/RTC wake 지원은 공식 예제 복사 전 검증. 어떤 GPIO가 wake 가능하고 RTC PCF8563 알람을 어떻게 지원하는지는 소스 확인.
- 네트워크 연결·HTTPS 및 display refresh의 실제 소모전류는 보드에서 직접 측정, 공식 low-power 데모의 14µA는 전체 대시보드 **기대 배터리 수명**이 아님.
- USB 전원 감지 실패 시 정책을 안전한 저빈도 스케줄로 fallback. 배터리 잔량 % 계산은 실제 방전곡선 없이 임의선형으로 보장 금지.
- `last_known_good` 캐시 유지하며 `최종 갱신 실패/오래된 표시`는 기상에도 보이게 한다. 중요한 실패는 사용자 버튼 없이 알아볼 수 있어야 함.

## 필수 테스트
- UTC 15:00=KST 익일 00:00 경계.
- 발표 5분 전→발표 5분 후 같은 API 요청 회차 선택.
- 3일 연휴, 월초·연초, 정부 API 공휴일 빈 응답, 영업일 다음날 오후.
- 장치 재부팅/RTC 초기화/NTP 실패/여러 번 wake 후 누적 오차.
- 100회 sleep-wake 루프, AP 모드 10분 timeout, 연결 실패 전력 폭주 방지.
- 배터리 충전/방전 실측 기록: USB 연결 여부·리셋률·wake별 소비량. 정확한 수명 예측은 계측 후에만 계산.
