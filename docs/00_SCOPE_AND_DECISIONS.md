# 00. 제품 요구사항과 확정 아키텍처

## 사용자 요구사항(고정)
- 구독료 0원 플랫폼, 자가 호스팅 서버·상시 PC 없음. Wi-Fi AP를 통한 **초기 기기 자체 설정**은 허용하되 운영 중 백엔드는 금지.
- 한국형 라이프스타일 정보 중심: 한국 날씨·미세먼지·환율·실내 온습도. 금융 확장으로 국내 주식 시세.
- 한국어 UI, 흑백/그레이스케일 800×480 가독성, 장기 안정성, 버튼 3개, 배터리 절전.
- 시작은 서울 기본 지역이지만 사용자가 동네/격자 및 측정소를 바꿀 수 있어야 함. 서울 자체를 단일 기상 격자로 간주하지 않음.

## 기능 범위 / 우선순위
### M0: 설치 전 개발
- 공식 E1001 예제 컴파일·드라이버 선택, Host Preview, 정적 한국어 UI, 가짜 JSON Fixtures, NVS 설정 스키마, 시계 테스트.
### M1: 독립 구동 MVP
- SHT40 내장 실내 온습도, KMA 날씨(현재·예보), AirKorea 대기질, EXIM 환율.
- 프로비저닝, HTTPS 검증, 캐시/출처·취득시각·데이터 유효성, 부분 갱신 조건부 지원, RTC 수면.
### M2: 금융 및 편의
- 금융위원회 최근 종가(익영업일 이후, 표시만), KIS 국내주식 현재가(키 보유자 옵션), 설정 페이지에서 관심종목 변경, 버튼 UI.
- 금융 API 계약 미검증 시 M1 출시는 가능하게 할 것(Feature flag).
### M3: 후속 아이디어
- 서울 교통(실제 출퇴근 시각, 온디맨드), 일정(로컬 ICS/URL 가능한 경우만), 고급 스파크라인, 자동 OTA.

## 주요 결정
- **개발 프레임워크**: PlatformIO + Arduino를 기본; 드라이버는 공식 LVGL/Seeed_GFX 예제 또는 E1001 GxEPD2 중 **공식 예제를 실빌드해 한 가지 채택**. UI 엔진은 RAM·갱신 시간 측정 후 결정; 처음부터 LVGL 강제 아님.
- **데이터 파이프라인**: E1001에서 직접 GET/POST, 공통 domain model에 정규화, 캐시 후 렌더. 복잡한 JavaScript·브라우저 사용 없음.
- **비밀 보호**: 공공 API 키는 디바이스 설정을 통해 입력. KIS App Secret은 금융 기능에서만 저장; 권한 축소 가능한지 검토. 로그 마스킹.
- **자체 설정화면**: 전원 후 미설정/버튼 롱프레스 시에만 자체 AP+HTTP 설정 포털. 인터넷에 개방되는 원격 운영 서버 아님.
- **데이터 갱신**: API 원본 게시 주기를 초과하여 불필요하게 호출하지 않으며, 화면 갱신은 실데이터 값 변경에만.
- **타임존**: `Asia/Seoul`, 타임스탬프 내부 표준은 Unix UTC, 화면 표현만 KST. 서버시간/RTC 시간 드리프트 처리.

## 성공 지표(계측 가능한 항목)
- 분리 네트워크가 아닌 **일반 가정용 2.4GHz Wi-Fi에서** 재부팅 후 무인 API 호출·표시·sleep/re-wake 작동 (실기 검증).
- 3개 버튼 입력이 각 1회 동작하고 오작동·반복 입력 없음 (실기).
- 2종 이상 서로 다른 공개 데이터 API 스키마 오류에도 WDT loop 없이 최신 정상 캐시 유지 (Host + 실기 확인).
- 모든 화면 정보에 `관측시각`/`기준일` 또는 `수신시각`, `출처`, 결측·지연 시각화 (UI 스냅샷).
- 나쁜 네트워크에서 무한 재연결/429 폭주 금지; 호출 상한 및 지수 백오프 증거 제공.
- 릴리스 후보는 빌드 및 테스트 성공, 기기 복구 절차 문서, 남은 미검증 표 포함.

## 하지 말아야 할 것
- '실시간'이라는 용어를 1초 단위 증권 체결가 보장으로 사용하지 않음.
- API 키 발급 없이 실제 API 통신 성공 주장 금지.
- 국내 금융정보 취득 시 비공식 HTML 스크래핑을 기본 아키텍처로 선택 금지.
- 공개 날짜·시세 예시를 실제 현재값으로 화면에 표기 금지.
