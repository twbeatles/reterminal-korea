기준: git tag `v1` + 호출 주기 변경([ADR 0016](adr/0016-refresh-cadence-and-manual-cooldown.md)). 코드를 읽고 정리한 분석이며, 실기로 확인한 것과 코드만 읽은 것을 구분해 적었다.

## 이번에 반영한 것

| 항목 | 내용 | 검증 |
|---|---|---|
| 페이지 전환 무호출 고정 | KEY0/KEY1은 API·Wi-Fi를 쓰지 않음을 테스트로 고정 | 호스트 테스트 |
| 수동 새로고침 쿨다운 | KEY2 연타가 같은 공급자를 120초 안에 다시 호출하지 않음 | 호스트 테스트(쿨다운 제거 시 실패 확인) |
| Wi-Fi 진단 로그 | `wifi: connected rssi=.. ms=..` / `wifi: FAILED status=.. ms=..` (SSID·비밀번호 미기록) | 빌드 SUCCESS, 실기 로그는 아직 보지 못함 |

## 후속 처리 (같은 날, [ADR 0017](adr/0017-v1-improvements.md))

아래 후보 중 1·2·3·5(빌드 설정 방식)·6은 코드로 처리했다. 4번은 종목별 등락률만 구현했고 지수는 응답 확인이 필요해 남겼다. 7·8은 실기·조사 항목이라 그대로다. 모두 호스트 테스트·빌드만 확인했고 기기에는 올리지 않았다.

## 점검에서 찾은 후보 (우선순위 순)

| # | 후보 | 근거(코드) | 위험/영향 | 규모 |
|---|---|---|---|---|
| 1 | Wi-Fi 끊김 후 재연결 | USB 상태에서 `ConnectWifi`는 공급자 기한이 올 때만 호출된다. 연결이 끊겨도 다음 기한까지 재시도하지 않는다. 끊김 사유 로그는 이번에 추가했으나 끊긴 순간(이벤트) 로그는 없다 | 끊긴 채 화면이 오래된 값으로 남는다. 사용자가 보고한 "와이파이 안 됨"과 일치할 수 있으나 원인은 미확인 | 작음 |
| 2 | 금융위 오후 호출 정책 | 13시 이후 1회만 허용, 기기 호출은 한 번도 확인 못함 | 종가가 비어 보임. 정책 변경 또는 오후에 실기 확인 필요 | 작음(확인) |

| 5 | 사용자 설정 갱신 주기 | `BaseInterval`이 상수. 포털 설정 없음 | 호출량을 사용자가 조절 못함 | 중간(스키마 변경) |

## 바로 하지 않은 이유

- 1번(재연결): 끊김 원인을 모르는 상태에서 재시도를 넣으면 로그 없이 배터리·호출만 늘릴 수 있다. 새 로그로 원인을 먼저 본 뒤 정책을 정하는 편이 안전하다.
- 5번: 설정 스키마 버전을 올리는 변경이라 마이그레이션 테스트가 같이 필요하다.
- 6번: 바꾸면 재빌드·재업로드가 필요하고 v1 기준점의 빌드 식별과 갈라진다. 요청이 있을 때 한다.
