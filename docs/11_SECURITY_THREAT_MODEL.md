# 11. 키·비밀 위협 모델과 저장 방침 (04 보충, U-11)

> NVS/Flash는 하드웨어 분실 시 비밀 완전 보호를 보증하지 않는다.
> 아래는 확정 방침이며, 안전한 것처럼 과장하지 않는다.

## 가정

- 공격자상: 분실·도난 기기의 플래시 덤프, 설정 포털 접근 시도, 로그 탈취.
- 보호 목표: 평문 키의 우발적 노출 방지 (로그·화면·포털·펌웨어·픽스처).
  국가기관급 하드웨어 내성 목표가 아니다.

## 규칙

- HTTPS 인증서 검증 기본, `setInsecure()`·HTTP 강등 금지 (TLS-01).
- 비밀은 NVS에만 저장하고, 포털 재조회·화면·로그에는 `등록됨/미등록`만 표시.
- 설정·캐시는 원자 쓰기 + CRC, 손상 시 안전 재설정 (CACHE-01).
- `secrets.*`, `.env`, `*.key`, `*.pem` 커밋 금지 — 공개 루트 CA만 예외.
- 증권사 키는 본인 실기기 입력만. 판매·재배포 구조로 확장 금지.
- UART/HTTP raw 캡처는 원본 커밋 금지 — `fixture_sanitizer` 세척본만 공유.

## 같은 Wi-Fi 포털 (ADR 0024)

- 공격자상 추가: 같은 LAN의 다른 단말, 악성 웹페이지(DNS 리바인딩·교차 출처 POST), 무선 구간 캡처.
- 대응: 화면 페어링 코드 + 단일 세션 + 시도 잠금, Host/Origin 검사, CSRF, 요청 크기·형식 제한, 응답에 비밀 미포함.
- 남는 위험: 평문 HTTP라 같은 Wi-Fi PSK를 아는 도청자는 입력 중인 키를 볼 수 있다. 완화는 경고·AP 경로 유지·짧은 세션이며 완전한 방어가 아니다.

## 미확정 (사용자 승인 전까지 손대지 않음)

- ESP32 flash encryption / secure boot 영구 fuse: 칩 스펙·복구 비용 조사 후
  별도 승인 필요. 공장 fuse 활성화는 어떤 자동화에도 넣지 않는다.
- 로컬 OTA 서명 키 관리: ADR 0002 도입 시 설계.
