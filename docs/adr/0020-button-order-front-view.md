# ADR 0020 — 버튼 역할을 앞에서 본 순서에 맞춤

- 상태: **[ADR 0021](0021-button-layout-nav-gray-action-green.md)로 대체됨.** 당시 채택(호스트 테스트·빌드·플래시), 물리 위치(녹색=KEY0)는 가정이었다. 날짜 2026-11-11.
- 요청: 앞에서 볼 때 왼쪽 회색 2개, 오른쪽 녹색 1개인데 오른쪽 두 버튼의 순서가 거꾸로 느껴진다. 앞에서 본 순서에 맞게 바꿔 달라.

## 근거와 가정

- 저장소에는 버튼의 물리 위치 기록이 없다(핀맵은 KEY0=GPIO3, KEY1=GPIO4, KEY2=GPIO5만 있음).
- 가정: 앞에서 볼 때 왼쪽→오른쪽이 **KEY2(GPIO5), KEY1(GPIO4), KEY0(GPIO3, 녹색)**. 종전 동작(KEY0=이전, KEY1=다음)이면 가운데=다음, 녹색=이전이라 "오른쪽 두 개가 거꾸로"라는 보고와 일치한다. 반대 배치였다면 보고된 증상이 생기지 않으므로 이 가정이 가장 부합한다. 그래도 직접 확인한 사실은 아니다.

## 변경

| 버튼(앞에서 볼 때) | 키 | 이전 | 이후 |
|---|---|---|---|
| 왼쪽 회색 | KEY2 | 새로고침 | 새로고침(그대로) |
| 가운데 회색 | KEY1 | 다음 화면 | **이전 화면** |
| 오른쪽 녹색 | KEY0 | 이전 화면 | **다음 화면** |
| 오른쪽 녹색 2초 | KEY0 길게 | 설정 포털 | 설정 포털(그대로, 절전 깨우기 키) |

- 구현은 `CyclePlanner`의 짧게 누르기 동작만 맞바꾼 것이다. 하드웨어 읽기(`ButtonDecoder`, 깨우기 EXT1)는 건드리지 않았다.
- 기기 화면의 도움말 문구도 위치 표현("가운데 ◀ 이전 / 오른쪽(녹색) ▶ 다음 / 왼쪽 새로고침")으로 바꿨다.
- 테스트: `test_cycle_planner`가 KEY0 짧게=다음, KEY1 짧게=이전(생활에서 이전은 마지막 탭), KEY0 길게=포털을 고정한다.

## 확인 방법

기기에서 버튼을 눌러 보고, 가정이 틀렸으면(예: 녹색이 KEY2) 이 ADR의 표만 바꿔 역할을 다시 배정한다. UART 로그의 `buttons: mask=`(KEY0=1, KEY1=2, KEY2=4)와 `button: event=..`로 어느 물리 버튼이 어느 키인지 확인할 수 있다.
