# ADR 0021 — 버튼 배치: 회색 둘은 화면 이동, 녹색은 새로고침·설정

- 상태: 채택(호스트 테스트·빌드·플래시). **물리 위치 대응(녹색=KEY0, 가운데=KEY1, 왼쪽=KEY2)은 가정이며 사용자 확인 대기.** 날짜 2026-11-11. [ADR 0020](0020-button-order-front-view.md)을 대체한다.
- 요청: 회색 두 버튼은 이전/다음 화면, 맨 오른쪽 녹색은 새로고침과 설정 포털.

## 배치 (앞에서 볼 때)

| 버튼 | 키 | 짧게 누르기 | 길게(2초) |
|---|---|---|---|
| 왼쪽 회색 | KEY2 (GPIO5) | **이전 화면** | - |
| 가운데 회색 | KEY1 (GPIO4) | **다음 화면** | - |
| 오른쪽 녹색 | KEY0 (GPIO3) | **새로고침** | **설정 포털** |

- 화면 이동 쪽(회색)은 어떤 API도 호출하지 않는다. 새로고침(녹색)만 공급자 호출을 일으키며, 공급자별 120초 쿨다운이 그대로 적용된다([ADR 0016](0016-refresh-cadence-and-manual-cooldown.md)).
- 시계가 확인되지 않은 상태의 새로고침은 NTP만 시도하고, 시계가 확인된 뒤에만 HTTPS를 호출한다(종전과 동일).
- 녹색(KEY0)이 절전 깨우기 키이므로, 깊은 잠에서 녹색으로 깨면 새로고침이 실행된다.

## 구현

`CyclePlanner`의 키 해석만 바꿨다. 짧게: bit2(KEY2)=이전, bit1(KEY1)=다음, bit0(KEY0)=새로고침. bit0 길게=포털. 버튼 읽기(`ButtonDecoder`)와 EXT1 깨우기 맵은 그대로다. 기기 화면 도움말도 "왼쪽 ◀ 이전 화면 · 가운데 ▶ 다음 화면 / 녹색 새로고침 · 녹색 2초 누르면 설정"으로 바꿨다.

## 검증

- 호스트: `test_cycle_planner`(KEY1=다음, KEY2=이전, KEY0 길게=포털, KEY0 짧게=새로고침과 시계 미확인 시 NTP만), `test_page_keys_never_call_api`(이전/다음을 6번 눌러도 HTTP·Wi-Fi 0회), `test_manual_refresh_cooldown`(녹색 연타 쿨다운). C++ 90개 통과.
- 실기: 플래시·부팅만 확인했다. 버튼을 눌러 본 확인은 없다. 가정이 틀리면(예: 녹색이 KEY2) 이 표의 키 번호만 다시 배정하면 된다. UART 로그 `buttons: mask=`(KEY0=1, KEY1=2, KEY2=4)와 `button: event=..`로 물리 버튼과 키의 대응을 확인할 수 있다.
