# ADR 0016 — 화면 전환과 API 호출 분리, 수동 새로고침 쿨다운

- 참고: 수동 새로고침 버튼은 이후 [ADR 0021](0021-button-layout-nav-gray-action-green.md)에서 녹색(KEY0 짧게)으로 바뀌었다. 아래의 "KEY2"는 당시 표기.
- 상태: 채택(호스트 테스트 통과). 실기 확인은 아래 "미검증" 참고. 날짜 2026-11-11.
- 요청: 화면을 넘길 때마다 API를 호출하지 말고 일정 주기로만 갱신해 호출 횟수를 줄인다.

## 코드 분석 결과 (v1 기준)

- 페이지 전환(KEY0 이전, KEY1 다음)은 이미 API를 호출하지 않는다. `PlanCycle`이 두 키에서 `connect_wifi=false`, `sync_clock=false`로 돌려주고, `RunCycle`은 이 경우 네트워크 단계를 건너뛰어 저장된 `Snapshot`만 다시 그린다.
- 주기 갱신은 이미 공급자별로 있다. 기본 간격(USB / 배터리): 기상 실황 30분 / 60분, 단기예보 발표 회차(상한 3h / 6h), 에어코리아 1h / 2h, 환율 12h / 24h, 금융위 하루 1회(평일 13시 이후), KIS 현재가 5분 / 15분(장중만). USB에서는 `main.cpp`가 30초마다 "기한이 된 공급자만" 확인한다.
- 호출이 늘 수 있는 곳은 KEY2(수동 새로고침) 한 곳이다. 모든 공급자를 간격과 무관하게 즉시 호출하고(시장·발표 회차·인증·Retry-After 조건은 유지), 연타를 막는 장치가 없었다. KIS는 토큰 발급이 분당 1회로 제한되어 연타 시 `RATE_LIMITED`를 만든다.

## 결정

1. 페이지 전환은 API를 호출하지 않는다는 점을 테스트로 고정한다(`test_page_keys_never_call_api`: 키를 6번 번갈아 눌러도 HTTP 요청 수와 Wi-Fi 연결 수가 변하지 않는다).
2. KEY2 수동 새로고침에 공급자별 최소 간격 `kForceMinGapSec = 120`초를 둔다. 같은 공급자를 마지막 시도 후 120초 안에는 다시 호출하지 않는다(`DueProviders`의 force 경로). 간격이 지나면 지금처럼 모든 공급자를 즉시 갱신한다(`test_manual_refresh_cooldown`). 쿨다운을 빼면 이 테스트가 실패함을 확인했다.
3. 주기 값 자체(5분/30분 등)는 바꾸지 않았다. 호출 예산(공급자별 일일 상한)과 사용자가 주기를 설정하는 기능은 아래 대안으로 남긴다.

## 영향

- 정상 사용(자동 주기, 페이지 전환)의 동작은 같다. 달라지는 것은 120초 안의 KEY2 재입력이 새 요청을 만들지 않는다는 점이다. 이때 화면은 보관된 데이터로 다시 그려진다.
- 하루 호출량(USB, 단순 추정): 실황 48, 예보 8, 에어코리아 24, 환율 2, KIS는 장중 약 6.5시간 × 12회 × (종목 4 + 토큰 재발급 시 1) = 최대 약 390. 공공데이터포털 개발계정(일 1만 건대)과 KIS 초당 제한 안이다. 실제 한도는 각 기관 약관·계정에 따르므로 이 수치는 확인된 한도가 아니라 코드 상 간격에서 나온 추정이다.

## 대안과 한계

- 사용자 설정 주기: 포털에 "갱신 주기(분)" 항목을 넣고 `BaseInterval`에 곱해 쓰는 방식. 설정 스키마 버전·마이그레이션·포털 UI·테스트가 함께 필요해 이번에는 하지 않았다.
- KEY2 자체를 배터리 모드에서만 쿨다운으로 두는 방식은 USB에서 연타 호출을 못 막아 채택하지 않았다.
- 쿨다운은 RAM의 `last_attempt_utc`를 쓴다. 재부팅 직후 값이 비어 있으면(보관 복구 전) 첫 새로고침은 통과한다.

## 미검증

- 실기에서 KEY2 연타 시 로그(`fetch:` 줄이 늘지 않음)와 화면 반응은 확인하지 않았다. 호스트 테스트 통과를 실기 정상으로 올리지 않는다.
