# ADR 0022 — Wi-Fi 연결 유지와 자동 재연결

- 상태: 채택. 기기(COM5)에서 부팅 직후 연결 확인. **끊김 복구 동작은 기기에서 재현하지 못했고 호스트 테스트로만 검증.** 날짜 2026-11-11.
- 요청: 갑자기 Wi-Fi가 연결되지 않는 현상 점검, 연결 안정성과 자동 재연결 구현.

## 점검 결과 (원인)

기기 UART 로그(`evidence/live-api-integration/wifi-idle-diagnosis-redacted.log`):

- 부팅 후 약 308초 동안 `wifi:` 로그가 한 줄도 없다가 다음 공급자 갱신 시점에 `wifi: connected rssi=-42 ms=2000`이 나왔다. 연결 자체는 2초 만에 되고 신호도 좋다(RSSI -42). **공유기·신호 문제가 아니다.**
- 원인은 펌웨어 정책이었다. 재부팅(또는 재플래시) 후 저장된 갱신 이력을 복원하면 "지금 호출할 공급자가 없음"으로 판단해 Wi-Fi 연결을 시작하지 않았다. 연결은 호출이 필요할 때만 했기 때문에, 그 사이 헤더 아이콘과 기기 탭에는 "Wi-Fi 미연결"로 보였다.
- 연결이 중간에 끊기는 경우도 같은 구조였다. 끊김 후 다음 갱신 시점까지 재연결을 시도하지 않았다(드라이버 자동 재연결에만 의존).
- 이번 점검 중에는 끊김 이벤트(`link lost`)가 한 번도 로그에 나오지 않았다. 즉 이전에 보셨던 "갑자기 연결 안 됨"은 이 유휴 상태(연결 시도 없음)로 설명되지만, 실제 링크 단절이 있었는지는 알 수 없다.

## 변경 (USB 전원일 때만)

- **부팅 시 선연결:** USB면 첫 화면을 그리기 전에 연결한다(갱신할 것이 없어도). 로그 `wifi: connected rssi=.. ms=..`.
- **감독기(`WifiSupervisor`, 순수 로직):** 끊김/미연결을 감지해 재연결한다.
  - 끊기면 10초 유예(드라이버 자동 재연결 먼저), 이후 시도.
  - 시도가 20초 안에 안 되면 실패로 세고 5초, 10초, 20초 … 최대 5분 백오프.
  - 4번째 시도마다 라디오 전체 리셋(드라이버 상태 고착 대비).
  - 복구되면 실패 횟수 초기화.
- **라디오 설정(USB):** 모뎀 절전 끔(`WiFi.setSleep(false)`), 자동 재연결 켬, 설정을 플래시에 매번 쓰지 않음(`persistent(false)`).
- **진단 로그:** `wifi: disconnected reason=N`(드라이버 사유 코드), `wifi: link lost`, `wifi: reconnect attempt=.. failures=..`, `wifi: radio reset + reconnect`, `wifi: link restored after_ms=.. rssi=..`, 차단 연결 실패 시 `status`와 `reason`. SSID와 비밀번호는 기록하지 않는다.
- **아이콘 갱신:** 연결 상태가 바뀌어 30초 이상 안정되면 헤더 아이콘을 한 번 다시 그린다. 5분에 한 번으로 제한해 끊김이 반복돼도 전자잉크가 깜빡이지 않는다(`AppState::redraw_requested`).
- 배터리(절전) 모드는 그대로다. 라디오는 갱신할 때만 켜고, 감독기는 동작하지 않는다.

## 검증

- 호스트: `test_wifi_supervisor_policy`(미연결 즉시 시도, 중복 시작 없음, 끊김 유예, 백오프 5/10/20초·상한 5분, 4번째 시도 리셋, 복구 시 초기화, 배터리·SSID 없음 무동작), `test_wifi_supervisor_redraw_is_debounced`, `test_redraw_request_triggers_one_render`. C++ 93개 통과, pytest 164개 통과.
- 실기: 부팅 직후 `wifi: connected rssi=-42 ms=1801` (2.5초)로 확인했다. 재부팅을 반복해도 매번 부팅 직후 연결됐다. 빌드 RAM 72,708 B, Flash 1,839,522 B(55.0%).
- 미검증: 공유기 재부팅·AP 끊김 때의 실제 재연결 시간, 사유 코드 분포, 장시간 안정성. 기기에서 연결을 일부러 끊어 본 적이 없다.

## 한계

- 링크는 살아 있지만 인터넷이 안 되는 경우(DNS/HTTP 실패)는 이 변경 범위 밖이다. 그 경우는 기존대로 공급자별 백오프로 처리된다.
- 공유기 쪽 문제(2.4GHz 채널 변경, MAC 필터, DHCP 임대)는 `disconnected reason` 코드로 원인을 좁힐 수 있다.
