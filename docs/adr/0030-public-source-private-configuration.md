# ADR 0030 — 공개 소스와 개인 설정 분리

- 상태: 구현 및 로컬 검증, 과거 작성자 개인정보 공개 게이트 미완료. 사용자 공개 저장소 준비 요청, 2026-11-13. 계정 정지로 push하지 않는다.
- 선택: 일반 `reterminal_e1001`은 기기 포털/NVS만 사용한다. 개발 환경에서만 `~/.config/kdash-e1001/kdash_private_credentials.h` 또는 `KDASH_PRIVATE_CONFIG_DIR`의 헤더를 include한다. 이 경로는 저장소 바깥이어야 한다. 키 값은 build_flags/CLI에 넣지 않는다.
- 실제 로컬 분리: 기존 ignored 개발 헤더와 자격정보 메모를 저장소 밖으로 옮기고 바이트 해시를 비교한 뒤 기존 사본을 제거한다. 헤더/메모의 내용·값·값 해시는 보고서에 출력하지 않는다. 현재 기기/로그 수집은 재시작하지 않는다.
- 공개 방지: 개발 바이너리에 고정 비밀 없는 `KDASH_PRIVATE_BUILD|END` marker를 넣고, 공개 패키징은 이 marker·실제 로컬 키/SSID의 바이트·환경 build override·개발 hook을 거부한다. 외부 개인 설정이 존재해도 일반 공개 빌드 자체는 가능하다.
- Git 검사: 인덱스와 선택한 reachable history의 모든 blob을 검사한다. 알려진 로컬 키/SSID(원문·URL 변형)와 기존 패턴을 검사하고, 위치/종류만 출력한다. 의도적으로 비밀 모양을 넣은 검출기 회귀 fixture는 검토한 정확한 blob hash만 예외이며 실제 로컬 값 일치는 예외 없이 실패한다. 파일이 바뀌면 예외가 사라진다.
- 개인정보 경계: Git 작성자 이메일도 별도로 점검한다. 기존 이력에 noreply가 아닌 주소가 확인돼 사용자에게 공개 작성자 이름/noreply 주소를 문의했다. 기존 이력 재작성·강제 push는 이번 구현에서 자동 수행하지 않는다. 이미지 OCR/알려지지 않은 비밀/기기 Flash/NVS의 추출 내성은 이 검사로 보증하지 않는다.
- 대안: `.gitignore`만 사용(과거 이력·강제 add·개발 바이너리 유출을 막지 못함), 키 값을 환경 C++ 매크로로 전달(컴파일 명령/로그 노출), 운영 백엔드로 이동(프로젝트 경계 위반).
- 검증: private 경로 검증·이력에만 남은 비밀·UTF-16/바이너리·공개 릴리스 오염 거부 테스트, 기본/외부 개인 개발 빌드. 결과는 `evidence/public-readiness-2026-11-13/summary.md`.
- 복원: 키는 외부 경로에 보존한다. 일반 빌드/포털 입력은 독립적이다. 구버전 개발 빌드로 돌아갈 때만 로컬 private 헤더를 구버전이 요구하는 ignored 위치로 별도 복사해야 한다.
